# iCE40 Global Buffer Usage Report

**Target:** iCE40-HX8K (Alchitry Cu v1), `ice40_alchitry_cu_top`  
**Toolchain:** Yosys 0.33 / nextpnr-ice40  
**Target frequency:** 25 MHz  

---

## Background

The iCE40-HX8K provides exactly **8 global buffer (`SB_GB`) slots**.  
Global buffers provide a dedicated low-skew routing network that is shared
across the entire device.  nextpnr-ice40 fills all eight slots automatically
during placement by promoting the highest-fanout signals that drive
synchronous-reset (`[reset]`) or clock-enable (`[cen]`) pins on flip-flops.

Because the resource is fixed at 8 and the tool always fills them if
enough candidates exist, the practical goal is to ensure the *right* signals
occupy the slots, and to avoid wasting slots on synthesis artifacts.

## Global Buffer Assignments

### Slot 1 — System Clock (PLL output)

| Field       | Value |
|-------------|-------|
| Signal      | `pll_clk_global` |
| Type        | clock |
| Fanout      | all flip-flops in design |
| RTL origin  | `ice40_alchitry_cu_top.sv` → `SB_PLL40_CORE` instance `pll_inst`, port `PLLOUTGLOBAL` |

The 25 MHz system clock generated by the on-chip PLL is inherently routed
on the global network via the `PLLOUTGLOBAL` output.  No `SB_GB` cell
appears in the post-synthesis netlist for this slot; the PLL drives the
global routing directly.

**Assessment:** Correct and mandatory use.  Cannot and should not be moved.

---

### Slot 2 — Main System Reset

| Field       | Value |
|-------------|-------|
| nextpnr net | `fpga_common_top_inst.cpu_inst.reset_ctrl.rst_n_out_SB_LUT4_I3_O` |
| Type        | `[reset]` |
| Fanout      | **1199** |
| RTL origin  | `rtl/common/primitives/reset_controller.sv` → output `rst_n_out` (becomes `rst_n_internal` in `top.sv`) |

The `reset_controller` module generates `rst_n_out` after waiting
`RESET_CYCLES` (25 000 000 cycles = 1 s) for the PLL to lock.  Every
synchronous flip-flop in the design is reset by this signal.  The
`_SB_LUT4_I3_O` suffix reflects a one-LUT inversion: the current RTL uses
active-low `rst_n`, but iCE40 `SB_DFFSR.R` is active-high.  Project guidance
now prefers active-high internal resets by default and reserves active-low
reset signals for external board-level exceptions, specifically to avoid this
kind of extra inversion and delay.

**Assessment:** Correct and mandatory use.  The 1199-fanout reset must be
on the global network to avoid enormous routing congestion and clock-enable
skew.

---

### Slot 3 — CPU FSM / Register-File Enable-Derived Reset Bus

| Field       | Value |
|-------------|-------|
| nextpnr net | `fpga_common_top_inst.cpu_inst.cpu_core.a_reg_write_SB_DFF_Q_D_SB_LUT4_O_I2[1]` |
| Type        | `[reset]` |
| Fanout      | **565** |
| RTL origin  | `rtl/common/cpu/cpu.sv` → `a_reg_write` (FSM control signal asserted in `S_REG_READ_WAIT`) |

`a_reg_write` is the one-bit control pulse that triggers capture of the
integer register-file read data (`a_reg <= rs1_data` in `S_REG_READ_WAIT`).
Its fanout in the RTL is only two flip-flops (`a_reg` and `b_reg`, 32 bits
each).

The 565-fanout "reset" bus visible in the netlist is **not** `a_reg_write`
itself but a deeply synthesised derived net.  Yosys's ABC/technology-mapping
passes can combine FSM-state bits with synchronous-reset/enable logic in ways
that produce a high-fanout net whose origin can only be reliably determined
by tracing the post-synthesis netlist JSON.  The `[reset]` classification
indicates it drives the `R` port of `SB_DFFSR` cells.

Possible explanations (require netlist-level investigation to confirm):

* The FSM state register encoding creates a partially-shared reset signal
  that propagates to many pipeline staging registers.
* Yosys combines `if (!rst_n) … else if (a_reg_write) …` blocks across
  multiple pipeline stages into a single high-fanout reset bus.

**Assessment:** Appropriate use of a global buffer slot given the observed
fanout.  Further investigation with `yosys … show -format dot` or by reading
the JSON netlist is needed before deciding whether RTL restructuring could
reduce this fanout.  As a general RTL guideline, datapath payload registers
that are guarded by a separate valid/pending bit should usually keep the
control bit on the reset path but leave the payload register itself
unreset; consumers must ignore the payload while invalid, and removing that
payload reset term helps avoid exactly this kind of reset-fanout growth.

### Slot 4 — SRAM BRAM Internal Synthesis Artifact

| Field       | Value |
|-------------|-------|
| nextpnr net | `…sram_periph.sram_inst.mem.0.21_RDATA_1_…_DFFSR_D_R` |
| Type        | `[reset]` |
| Fanout      | **32** |
| RTL origin  | `rtl/common/memory/sram.sv` / `rtl/common/peripherals/sram_peripheral.sv` — BRAM block 0, data slice 21, RDATA port (bank 1) |

The `SB_RAM40_4K` block used for the 3072-word SRAM infers multiple BRAM
instances.  One BRAM's RDATA output propagates through a long chain of LUTs
and ultimately drives the `R` pin of 32 `SB_DFFSR` flip-flops.

The most likely source is the `split_first_rdata` register inside
`sram_peripheral.sv`, which latches `sram_rdata` during the
`S_READ_SPLIT_CAPTURE` state and is unconditionally reset to zero:

```systemverilog
// sram_peripheral.sv (simplified)
if (!rst_n) begin
    split_first_rdata <= 32'h0;   // Reset branch
end else begin
    S_READ_SPLIT_CAPTURE: split_first_rdata <= sram_rdata;
end
```

The BRAM RDATA path feeding into the D-input logic, combined with the
synchronous reset, creates a high-fanout signal from the BRAM output that
nextpnr classifies as `[reset]`.

**Assessment:** Synthesis artifact.  Fanout 32 is low enough that routing
without a global buffer is feasible on a less-congested device.  On the
HX8K at 72% LUT utilisation the tool promotes it to reduce routing pressure.
Elimination would require non-trivial restructuring of `sram_peripheral.sv`
(e.g. separating the BRAM output pipeline from the reset path).  This is a
good example of the broader rule that payload-only datapath registers should
not be reset when a separate valid/control signal already guarantees the
value is ignored until rewritten.  Deferred.

### Slot 5 — CSR File Initialisation Pending

| Field       | Value |
|-------------|-------|
| nextpnr net | `fpga_common_top_inst.cpu_inst.cpu_core.u_csr_file.csr_init_pending_SB_LUT4_I3_O` |
| Type        | `[reset]` |
| Fanout      | **26** |
| RTL origin  | `rtl/common/cpu/csr_file.sv` → `csr_init_pending` |

`csr_init_pending` is a 1-bit flag that tracks whether the CSR BRAM has
completed its post-reset initialisation sequence.  It is set during reset
and cleared once all machine-level CSR entries have been written.

```systemverilog
// csr_file.sv (simplified)
always_ff @(posedge clk) begin
    if (!rst_n)           csr_init_pending <= 1'b1;  // set on reset
    else if (init_done)   csr_init_pending <= 1'b0;  // clear when done
end
```

The `_SB_LUT4_I3_O` suffix shows it passes through an inverter before
driving `SB_DFFSR.R` pins.  With fanout 26 it was not promoted before the
`sram.sv` fix freed a slot; it now benefits from global routing.

**Assessment:** Appropriate use.  The CSR initialisation flag is a
legitimate high-fanout reset signal.  No change required.

### Slot 6 — Decoder `instruction_valid` Clock Enable

| Field       | Value |
|-------------|-------|
| nextpnr net | `…cpu_core.u_decoder.instruction_valid_SB_LUT4_I1_I2_SB_LUT4_I2_O[0]` |
| Type        | `[cen]` |
| Fanout      | **86** |
| RTL origin  | `rtl/common/cpu/decoder.sv` → output `instruction_valid` |

`instruction_valid` is asserted when the decoder recognises the current
instruction word.  It gates instruction processing throughout the CPU
pipeline.  `cpu.sv` ANDs it into `is_instruction_valid_reg`, which
participates in fetch/execute validity checking across many pipeline stages.

**Assessment:** Appropriate use of a global buffer slot.  High fanout is
inherent to the CPU's instruction-validity mechanism.  No change required.

### Slot 7 — AMO ALU Request Sent Clock Enable

| Field       | Value |
|-------------|-------|
| nextpnr net | `…cpu_core.alu_req_sent_rmw_SB_LUT4_I0_O_SB_LUT4_I2_O[3]` |
| Type        | `[cen]` |
| Fanout      | **73** |
| RTL origin  | `rtl/common/cpu/cpu.sv` → `alu_req_sent_rmw` |

`alu_req_sent_rmw` tracks whether the ALU handshake has completed during an
atomic read-modify-write (A-extension AMO) operation.  The CPU uses it to
guard the subsequent data-memory write request:

```systemverilog
// cpu.sv
alu_in_valid   = !alu_req_sent_rmw;
dmem_req_internal = alu_req_sent_rmw && alu_out_valid;
```

Its derived signal has fanout 73 after synthesis because it participates
in both the state-machine next-state logic and multiple pipeline-register
enable conditions.

**Assessment:** Appropriate use.  AMO control is a legitimate high-fanout
enable path.  No change required.

### Slot 8 — Host Bus Mux Response-Wait Clock Enable

| Field       | Value |
|-------------|-------|
| nextpnr net | `…cpu_host_bus_mux.waiting_for_resp_SB_LUT4_I1_O_SB_LUT4_I3_O_SB_LUT4_I2_O` |
| Type        | `[cen]` |
| Fanout      | **67** |
| RTL origin  | `rtl/common/io/host_bus_mux.sv` → `waiting_for_resp` |

`waiting_for_resp` tracks whether a memory request has been issued and is
awaiting a data-channel response.  It gates the address-channel ready signal
and participates in the host bus arbitration logic:

```systemverilog
// host_bus_mux.sv
assign cpu_mem_a_ready = !pending_req_valid && !waiting_for_resp && !pending_resp_valid;
```

After the `sram.sv` fix `mem_req_inflight` from `cpu.sv` (previously in
this slot) was displaced by `waiting_for_resp`, which nextpnr determined
was more beneficial to promote in the new placement.

**Assessment:** Appropriate use.  Bus arbitration state is a legitimate
high-fanout enable path.  No change required.

## Change Made: `sram.sv` Read Pipeline Unification

Before this PR, `sram.sv` contained two generate blocks:

```
gen_full_range    — DEPTH == 2^ADDR_WIDTH (clean unconditional read)
gen_bounded_range — DEPTH  < 2^ADDR_WIDTH (conditional read with else 0)
```

The `gen_bounded_range` path used a conditional synchronous-clear on
`read_data_pipe`:

```systemverilog
// OLD — caused SB_DFFSR synthesis for read_data_pipe (32 cells)
if ({1'b0, raddr} < (ADDR_WIDTH+1)'(DEPTH)) begin
    read_data_pipe <= mem[raddr];
end else begin
    read_data_pipe <= 32'b0;   // synchronous clear → SB_DFFSR
end
rdata <= read_data_pipe;
```

Yosys mapped this to 32 `SB_DFFSR` cells whose shared reset bus
(`rdata_SB_DFFSR_Q_R`) nextpnr promoted to a global buffer slot.

The fix removes the generate blocks and uses a single `always_ff`:

```systemverilog
// NEW — unconditional read; write still bounds-checked
if (we && ({1'b0, waddr} < (ADDR_WIDTH+1)'(DEPTH))) begin
    // ... byte-write lanes ...
end
read_data_pipe <= mem[raddr];   // always read — clean DFF, no SB_DFFSR
rdata <= read_data_pipe;
```

The write bounds check is retained.  For power-of-two `DEPTH`, the
expression `{1'b0, waddr} < DEPTH` is a static tautology which Yosys
constant-folds away, leaving `if (we)` as before.

**Effect on global buffer usage:**

| Signal                           | Before | After |
|----------------------------------|--------|-------|
| `sram_inst.rdata_SB_DFFSR_Q_R`  | Slot used | **Eliminated** |
| `csr_file.csr_init_pending`      | Not promoted | **Gains slot** |
| Total `SB_GB` slots used         | 8/8    | 8/8   |

The total count stays at 8/8 because the freed slot is immediately claimed
by `csr_init_pending` (fanout 26), which previously had no global buffer.
The overall netlist quality improves: one synthesis artifact removed, one
genuine control signal gains lower-skew routing.

**SB_DFFSR cell count:** 451 → 418 (−33 cells)  
**SB_DFF cell count:** 315 → 347 (+32 cells)

## Recommendations / Open Items

1. **Slot 3 — `a_reg_write`-derived 565-fanout reset bus (cpu.sv)**  
   Trace this net in the post-synthesis JSON netlist
   (`rtl/fpga/build/ice40_alchitry_cu/riscv_fpga.json`) to identify its precise RTL
   origin.  A 565-fanout reset signal from a register-write enable is
   architecturally unexpected and may indicate an unintended Yosys
   optimisation.  If the fanout can be reduced through RTL restructuring
   (e.g. separating the reset term from the enable term), global buffer slot 3
   could potentially be freed for use by higher-priority signals.

2. **Slot 4 — `sram.mem.0.21_RDATA_1_*` BRAM artifact (sram_peripheral.sv)**  
   The remaining SRAM global buffer slot is driven by the BRAM RDATA path
   through the `sram_peripheral.sv` state machine.  Potential mitigations:  
   a. Add an output register stage in `sram_peripheral.sv` to break the BRAM
       RDATA path before it reaches registers with synchronous resets.  
   b. Change `split_first_rdata` from a synchronously-reset register to one
       that captures on a gated clock-enable only (removing the `if (!rst_n)`
       reset branch for this specific register, while keeping the associated
       control/valid state reset so the payload is ignored until recaptured).  
   Both require careful functional verification.

3. **General RTL guidance**  
   For datapath registers whose contents are only meaningful when accompanied
   by a separate `valid`, `pending`, or equivalent control bit, prefer
   resetting the control bit only.  Write or refresh the payload whenever new
   data is captured, typically in the same branch where the control bit is
   asserted, instead of forcing the payload through the global reset network.
   This reduces reset-path fanout and routing congestion on resource-constrained
   FPGA targets.

4. **BRAM pressure (30/32 = 93%)**  
   The design is close to the ICESTORM_RAM ceiling.  Future additions using
   BRAM (e.g. larger SRAM, deeper FIFO, additional CSR BRAM) will trigger
   resource overflow.  Monitor BRAM usage with each significant RTL change.

5. **LUT pressure (72%)**  
   Comfortable headroom remains for the current feature set (M and F
   extensions disabled on iCE40).  Enabling M or F extensions is not
   possible on HX8K due to combined LUT + BRAM constraints.
